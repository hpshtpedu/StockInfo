# 股市大局觀

個人用的手機看盤儀表板：一頁看完台股盤中、國際市場、台股盤後的狀況。每個指標盡量附上**有歷史回測依據的判斷 badge**，而不只是列出數字。

- 網頁：GitHub Pages（`docs/`），深色主題，台股慣例紅漲綠跌，以 iPhone 寬度為主要設計目標
- 報價：Cloudflare Worker（`worker/`），網頁每 2 分鐘更新一次
- 每日資料：GitHub Actions 每晚排程（`scripts/`），結果存成 `docs/*.json`
- **純個人使用**：交易所資料受證交所《交易資訊使用管理辦法》規範，請勿公開散佈網址。網頁已設定 `noindex`，不讓搜尋引擎收錄。

---

## 架構

```
手機瀏覽器 ──每 2 分鐘──▶ Cloudflare Worker /quotes ──▶ Yahoo、證交所、期交所…
     │                    （Cache API 快取，看的人再多，上游也只被抓一次）
     └──▶ GitHub Pages：docs/index.html + docs/*.json（每晚排程產生的歷史資料）
```

| 部分 | 位置 | 部署方式 |
|---|---|---|
| 網頁 | `docs/index.html`（單一檔案，無建置步驟） | 推到 `main`，GitHub Pages 約 5–10 分鐘後更新。瀏覽器會快取約 10 分鐘，網址加 `?v=數字` 可強制取得新版 |
| 報價中繼 | `worker/src/index.js` | 推到 `main` 且改到 `worker/**` 時，自動部署（`.github/workflows/deploy-worker.yml`，需要 secrets `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`） |
| 每日資料 | `scripts/*.py`（只用標準函式庫，`build_events.py` 另外需要 `holidays`） | `.github/workflows/daily-data.yml`：週一到週五台灣時間 21:30、23:00 各跑一次，改到 `scripts/**` 時也會觸發。同一時間只跑一個，排隊的那次會讀取最新的 `main` |

排程機器人會提交 `docs/*.json`，所以**推送前要先 `git pull --rebase`**。

## 資料來源與禮貌原則

每個來源都控制在低頻率、有快取、遵守 robots.txt，避免被誤認成攻擊。有官方或合規的來源就用官方的；只有灰色或不穩定來源的指標就不做（這個網頁要「細水長流」）。

| 資料 | 來源 | 頻率 |
|---|---|---|
| 國際報價（費半、TSM、小納、韓、日、布蘭特、美債、台幣） | Yahoo Finance | Worker 每 2 分鐘（有快取） |
| 加權、台指期、持股、漲跌家數 | Yahoo 奇摩股市 | 同上；台股休市日 05:00 後改成每小時 |
| 三大法人、融資、休市日 | 證交所網站 / OpenAPI | 公布後才抓，抓到就保留到下一次公布 |
| 外資台指淨 OI、散戶多空比、台指VIX | 期交所網站 CSV / 每月檔案 | 每天公布後抓一次 |
| 產業收盤成交比重（不顯示，供日後回測） | 證交所 BFIAMU | 每晚 1 次，外加往回補 5 天到 2025 年初 |
| 八大行庫 | HiStock（robots.txt 允許） | 一天最多一次，休市日不抓 |
| 經濟日曆 | FRED、Fed、`holidays` 套件、NVIDIA RSS、Yahoo 行事曆 | 每晚 |

台股休市日在 Worker 的快取規則裡視為週末，不會重抓台股資料。每晚排程中只跟台股有關的腳本，會先確認當天有沒有加權收盤，休市就跳過。

## badge 原則

- **badge 寫數字代表的意義**（例如「護盤」），數字本身放在卡片內容裡。
- **實心底色** = 少見、達門檻才出現的事件；**文字顏色** = 幾乎一直顯示的狀態；**灰色** = 中性說明。
- **門檻要有回測依據**，目標是大約只在 10–15% 的日子亮起。用長期資料驗證後沒有支持的「體感」badge 一律拿掉。

### 目前的 badge

## 正二風向球

回答「**這 10 天適不適合加碼正二（00685L）**」。規則依 2006–2026 年的長期回測訂定，數字是加權指數之後 10 / 20 個交易日的平均漲跌：

| 燈號 | 條件 | 10 日 / 20 日 |
|---|---|---|
| **加碼好時機** | 台指VIX ≥ 25，或散戶多空比 < 0（恐慌、散戶轉空時買） | +1.5% / +2.9% |
| **可加碼** | 費半站上 20 日均線，且加權站上 60 日均線 | +0.5% / +1.0% |
| **按兵不動** | 以上皆非（趨勢轉弱、市場又平靜） | 0.0% / +0.3% |

- 模擬每 10 天買一次：買進後 20 天平均 +1.94%，每期第一天就買是 +1.53%；只跳過約 8% 的期數。
- **等待時機**（個人紀律，未回測）：可加碼時，若在 09:30 前、00685L 現價高於當日成交均價，或 5 分鐘內仍創當日新低，就先等。
- 燈號只管「何時加碼」，**不負責減碼**。長期回測找不到能抵銷交易成本的減碼訊號。
- 回測不支持、已經拿掉的規則：乖離過熱（禁止追高）、大盤急跌、正二磨損、散戶過熱、國際風向總分。

### 回測的重點結論

- **VIX 是最強的訊號**：趨勢轉弱但 VIX ≥ 25 時，之後 20 日平均 +5.4%；趨勢轉弱且 VIX 低時只有 +0.3%。
- **VIX 第一次收盤破 40**（2016 年起 7 次）：隔天買進後 20 日有 6 次上漲，60 日全部上漲。但 20 日內仍可能再跌 5–8%，要分批。
- **恐慌就買不只是近年現象**：用美國 VIX（與台指VIX 相關係數 0.62）回推 2006–2015，VIX ≥ 25 時買台股，之後 20 日平均 +2.1%（全部日子 +0.3%）。
- **2008 的教訓**：VIX 破 40 後台股又跌了約兩個月（之後 20 日平均 −3.5%），而年初「趨勢轉弱又平靜」的緩跌階段最慘（−6.9%），正好是「按兵不動」擋掉的情況。大跌時的加碼要拆成 3–4 批、每批間隔兩週以上。
- 乖離過熱後通常**繼續漲**，乖離超跌後也**不特別好**；融資維持率、外資淨 OI 變化都沒有可靠的預測力。
- 限制：回測期間以多頭為主；VIX 門檻 25 是看過分組結果後挑的；散戶多空比只有 2020 年後的資料；回測用的是加權指數，正二是 2 倍，賺賠都會放大。

## 維護備忘

- **改網頁前先在本機實際跑過**：這台電腦沒有 Node。做法是把 Worker 的 `/quotes` 存成檔案，複製 `docs/*.json`，把 `index.html` 裡的 API 網址換成本機檔案，用 `python -m http.server` 開起來，再用 Edge 無頭模式 `--dump-dom` 確認狀態列顯示「更新 HH:MM」，不是「更新失敗」。
- **長期回測資料**：`mm_data/` 是從 MacroMicro 圖表手動匯出的長期資料（VIX、外資 OI、散戶多空比、融資維持率），只供本機分析，已加入 `.gitignore`，**不要提交**。匯出方法：在瀏覽器 console 執行
  ```js
  copy(Highcharts.charts.find(c => c && c.series).series.map(s => ({ name: s.name, data: s.options.data })))
  ```
  執行前先把圖表範圍調到最長，Highcharts 通常只載入目前顯示範圍的資料。
- **待辦**：`docs/sector_history.json`（證交所收盤產業比重）每晚往回補，約 2026/11 下旬補到 2025 年初後，回測「金融爆量是否預示行情末段」等假說。只有資料支持、而且有明確操作意義時，才加回 badge。
